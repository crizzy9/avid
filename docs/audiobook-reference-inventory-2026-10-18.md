# Audiobook reference inventory — 2026-10-18

This is a planning reference for making Avid a primary audiobook application. It records publicly verifiable behavior and settings from Plappa, Absorb, and the official Audiobookshelf client. It is not a claim that Avid implements these features, or that source inspection proves device reliability. No reference implementation was copied and no user server was contacted.

## Read along: current Absorb behavior and BookOrbit integration

Absorb v1.12.0 advertises narration highlighting by word or sentence, automatic page following, free browsing with a return-to-narration action, and live transcripts even for streamed audio without an ebook. These are shipped release claims, not evidence that arbitrary editions align perfectly. [Stable release](https://github.com/pounat/absorb/releases/tag/v1.12.0).

The pinned source adds these controls and operating details:

- Opt-in on-device transcription with downloadable tiny/base/small Whisper models. The current source chooses among installed models based on whether exact ebook text is available and the feature's speed/accuracy need; it is not evidence that users can select any model independently for every feature.
- Transcript font size/line count/full-cover mode, read-along color and word/sentence mode, cache clearing, and separate remembered transcript timing offsets for Bluetooth and other outputs.
- Find the ebook position from recently heard audio; find the audio position from selected text; choose whether a successful audio find stays in the reader, opens the player, or starts read along. Previously found positions and transcript lines are reused.
- A foreground pipeline processes audio windows ahead of playback and exposes waiting/slow-device states. It stops transcription when backgrounded; this is separate from native audio continuing in the background.
- Transcript lines distinguish text corrected against the ebook from recognized speech and estimated previews. Some timings can be interpolated between heard anchors; therefore a visual word highlight is not proof of measured per-word timing.

Sources: [transcription service](https://github.com/pounat/absorb/blob/b8880f75301a57b4843de1ebf8e23c5eeb3e6e9e/lib/services/transcription_service.dart), [settings](https://github.com/pounat/absorb/blob/b8880f75301a57b4843de1ebf8e23c5eeb3e6e9e/lib/services/player_settings.dart#L209), [find in ebook](https://github.com/pounat/absorb/blob/b8880f75301a57b4843de1ebf8e23c5eeb3e6e9e/lib/services/find_in_ebook.dart), [foreground transcript pipeline](https://github.com/pounat/absorb/blob/b8880f75301a57b4843de1ebf8e23c5eeb3e6e9e/lib/services/lyrics_service.dart), [stored line provenance](https://github.com/pounat/absorb/blob/b8880f75301a57b4843de1ebf8e23c5eeb3e6e9e/lib/services/transcript_line_store.dart), [alignment timing semantics](https://github.com/pounat/absorb/blob/b8880f75301a57b4843de1ebf8e23c5eeb3e6e9e/lib/utils/transcript_align.dart).

BookOrbit support uses an adapter to existing book/file/audiobook contracts. For this flow the inspected client reads `GET /api/v1/audiobooks/:bookId/manifest`, streams `/api/v1/audiobooks/:bookId/assets/:assetId/content`, and fetches ebook content from `/api/v1/books/files/:fileId/serve`. It maps native file positions onto the book timeline. Its local media proxy supplies bearer authentication to native consumers. Local files or bounded portions of streamed audio are decoded, transcribed on the device, and matched against ebook text on the device; the inspected BookOrbit adapter does not call a server transcript/alignment endpoint. This establishes how **this client** works, not the complete set of BookOrbit server capabilities. Avid should audit advertised server contracts independently before declaring a feature unavailable. [BookOrbit adapter](https://github.com/pounat/absorb/blob/b8880f75301a57b4843de1ebf8e23c5eeb3e6e9e/lib/services/bookorbit_api_service.dart#L1129), [asset/ebook routing](https://github.com/pounat/absorb/blob/b8880f75301a57b4843de1ebf8e23c5eeb3e6e9e/lib/services/bookorbit_api_service.dart#L3406), [local/streamed source selection](https://github.com/pounat/absorb/blob/b8880f75301a57b4843de1ebf8e23c5eeb3e6e9e/lib/services/transcription_service.dart#L320), [EPUB cache](https://github.com/pounat/absorb/blob/b8880f75301a57b4843de1ebf8e23c5eeb3e6e9e/lib/services/ebook_cache.dart#L210).

For Avid, full-book matching quality is a separate acceptance gate: exact edition selection, whole-track duration/index integrity, repeated passages, narration introductions/omissions, errors, seeks, stale assets, bounded memory and device runtime all need measured evidence. Matching must keep uncertain gaps and distinguish measured timing from estimates. Nothing above establishes that processing short excerpts proves full-book quality.

## Explicit Phase 3 and platform boundaries

The reference feature set includes substantial offline behavior. Record it now, but keep these implementations in **Phase 3**: queued/resumable/background/batch downloads; cellular/Wi-Fi download rules; auto-download on stream; next-N series/show/queue downloads; completed-download cleanup; storage location/quota/cache controls; signed-out access to downloaded titles; cold offline library/search; durable offline positions/notes/bookmarks/highlights; pending writes and conflict reconciliation; backup/restore and cross-device settings sync; standalone watch downloads. Absorb's settings backup can optionally contain account credentials, which is a separate explicit data-export decision. [Download settings](https://github.com/pounat/absorb/blob/b8880f75301a57b4843de1ebf8e23c5eeb3e6e9e/lib/screens/settings_search_index.dart#L110), [backup service](https://github.com/pounat/absorb/blob/b8880f75301a57b4843de1ebf8e23c5eeb3e6e9e/lib/services/backup_service.dart), [offline bookmark queue](https://github.com/pounat/absorb/blob/b8880f75301a57b4843de1ebf8e23c5eeb3e6e9e/lib/services/bookmark_service.dart#L112).

A prepared Read & Listen package and its reusable alignment remain Phase 2's bounded exception; that does not imply a durable offline editing/sync system. Ordinary player preferences, an explicit queue, and accidental-seek recovery also need not wait for the offline phase merely because they are local application state. The [master plan](phase-2-audiobook-plan.md) includes credential-free settings-only export/import in Phase 2; the broader backup/restore and reconciliation above refer to full user data and cross-device state.

Native integration needs separate platform acceptance. Plappa lists iOS/iPadOS 16 and watchOS 10; Absorb lists Android 7 and iOS 16. These minima do not change Avid's supported OS promise automatically. ABS gates motion reset, scheduled sleep and reset feedback mainly to Android; Absorb gates silence skipping/surround and some media controls to Android, and output selection differs by build. CarPlay, widgets, watch, motion, interruptions, Bluetooth timing and background audio cannot be accepted solely through a web harness. [Plappa compatibility](https://apps.apple.com/us/app/plappa/id6475201956), [Absorb requirements](https://github.com/pounat/absorb/blob/b8880f75301a57b4843de1ebf8e23c5eeb3e6e9e/README.md), [ABS platform guards](https://github.com/advplyr/audiobookshelf-app/blob/7014e04e6febcc5fd326e816a57b1065817e85f5/pages/settings.vue#L71).

Server user administration, backup jobs, metadata-provider configuration, import/download approval, file encoding/embedding, deletion, and podcast fetching are reference-app capabilities but are not prerequisites for audiobook playback parity. Unsupported server operations should be tracked against actual contracts; the listening design should not be artificially limited by them. General reader/Pencil enhancements stay Phase 4 and broad appearance work stays Phase 5.

No verified primary evidence in this review establishes general A–B loop playback, independent pitch control, or universal silence skipping in all three products. Those may be useful Avid additions, but must be labeled product decisions rather than asserted reference parity.
