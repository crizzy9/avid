# KOReader positions and file identity

The Avid integration follows BookOrbit v3.3.0, commit `e767358443419253eeed782518d6fc4f675d69fd`. BookOrbit owns the EPUB conversion between native CFIs and CREngine XPointer positions. Avid does not manufacture an XPointer from a percentage, title or guessed chapter, and does not treat an XPointer as a CFI. See the pinned [KOReader progress service](https://github.com/bookorbit/bookorbit/blob/e767358443419253eeed782518d6fc4f675d69fd/server/src/modules/koreader/koreader.service.ts) and [position converter](https://github.com/bookorbit/bookorbit/blob/e767358443419253eeed782518d6fc4f675d69fd/server/src/modules/position-converter/position-converter.service.ts).

## Reading and writing

`BookOrbitClient.getKoreaderCheckpoint(identity)` reads ordinary authenticated `GET books/files/:fileId/progress`. The result preserves both `cfi` and the raw `koreaderProgress`, together with account, book and exact file identity. PDF/comic positions use the server's one-based `pageNumber`. If the server could not convert an EPUB position, the snapshot retains the native evidence but returns no reader anchor. It does not replace that missing location with a percentage-derived CFI.

When a native locator exists, the client also reads `GET koreader/books/:bookId/progress`. This management endpoint requires the account's `koreader_sync` permission. Its `bookFileId` and canonical percentage must match the file checkpoint before Avid uses `canonicalUpdatedAt`. This matters because the server deliberately preserves the previous **web** timestamp when KOReader writes file progress. A 403/404/405, a different selected edition, or mismatched canonical percentage leaves the native event time explicitly unknown. A file-modified warning on the canonical KOReader state blocks automatic restoration. These are read-only JWT routes; Avid does not request, create or store KOReader device credentials. The [repository source](https://github.com/bookorbit/bookorbit/blob/e767358443419253eeed782518d6fc4f675d69fd/server/src/modules/koreader/koreader.repository.ts) and [dashboard types](https://github.com/bookorbit/bookorbit/blob/e767358443419253eeed782518d6fc4f675d69fd/packages/types/src/koreader.ts) define this distinction.

The ordinary `getProgress()` path uses that checkpoint and carries it as optional `koreader` metadata on the returned anchor. It remains JSON-serializable for the existing account-scoped checkpoint store. The `getKoreaderCheckpoint()` method also exposes an unresolved native locator when no usable reader anchor exists. No converter precision flag appears on file progress, so a supplied CFI is labeled **server-provided, precision unspecified**, never certified exact.

Ordinary `saveProgress()` retains a server-supplied native locator only when the file/account binding, CFI and percentage still describe the same point. Moving in Avid drops the obsolete native locator: on this server, omission clears it and BookOrbit converts the new CFI when KOReader next pulls. For PDF/comics, Avid sends the same positive page in `pageNumber` and the native page string in `koreaderProgress`. This is fixed-page encoding, not a reflowable-text conversion. A webtoon within-page offset has no KOSync equivalent and remains device-local. Source: [file progress DTO and service](https://github.com/bookorbit/bookorbit/blob/e767358443419253eeed782518d6fc4f675d69fd/server/src/modules/book/dto/save-progress.dto.ts) and [paged position routing](https://github.com/bookorbit/bookorbit/blob/e767358443419253eeed782518d6fc4f675d69fd/server/src/modules/koreader/koreader-progress-position.util.ts).

## Fingerprints

`computeKoreaderFingerprint(blob)` reads at most twelve 1 KiB samples at offsets 0, 1 KiB, 4 KiB, 16 KiB, continuing by powers of four through 1 GiB. A partial final sample is included. The independent bounded MD5 implementation matches the pinned [BookOrbit file hash algorithm](https://github.com/bookorbit/bookorbit/blob/e767358443419253eeed782518d6fc4f675d69fd/server/src/common/utils/file-hash.utils.ts) and official [KOReader `util.partialMD5`](https://github.com/koreader/koreader/blob/master/frontend/util.lua). Filename mode is a different KOReader option; Avid does not substitute a filename hash or title match.

Pass the resulting `{algorithm,value,sizeBytes}` as `identity.fingerprint` to `getKoreaderCheckpoint`. The snapshot preserves it. Before restoring a saved snapshot against newly obtained bytes, call `koreaderRestoreAnchor(snapshot, currentBinding)` with the newly computed fingerprint; mismatched fingerprints or sizes fail explicitly. The generic `getProgress()` method cannot compute a file hash without the file bytes, so callers requiring that additional check must use the explicit snapshot API. The pinned file-progress response does not expose the server's intrinsic file hash, and Avid does not invent one from metadata.

Partial MD5 is a compatibility identifier, **not a complete content-integrity proof**. An edit outside sampled regions can leave it unchanged. It never replaces authenticated account identity and exact BookOrbit file IDs. Converted or rewritten editions may legitimately differ; no automatic manual-hash-link mutation is performed.

## Evidence and remaining qualification

Twenty-five offline tests cover standard MD5 vectors, the server's sampled-block pattern, bounded reads through 1 GiB, unsampled-edit limitations, exact native-string preservation, server-provided CFIs, unavailable conversions, page/webtoon serialization, native timestamp selection, account/file/hash conflicts, modified-file warnings, stale native-locator removal and read-only integration routes. API fixture tests validate Avid's use of the contract; they do not execute BookOrbit's converter or claim an actual device round trip.

Physical KOReader acceptance still requires the same accessible file on a disposable writable server and device: read in Avid, sync KOReader, move forward and backward, then return to Avid while checking exact file and native point preservation. Include changed-file and missing-conversion cases. The supplied server remains untouched. Official [BookOrbit KOReader guidance](https://bookorbit.app/koreader) also distinguishes native positions from approximate cross-reader restoration and requires matching document fingerprints.
