# BookOrbit contract implemented by Avid

Inspected on October 9, 2026 against the [BookOrbit v3.3.0 release source](https://github.com/bookorbit/bookorbit/tree/v3.3.0), commit `e767358443419253eeed782518d6fc4f675d69fd`. The actual adapter passed [14 real write/read checks](bookorbit-smoke.md) against an isolated loopback instance built from that commit. This evidence does not certify every deployment, account permission, proxy or device. No server implementation has been copied into Avid. API requests and domain mappings are independently implemented.

All routes below are relative to the configured server's `/api/v1` prefix. Deployment subpaths are preserved. A same-origin transport can override the network base using `transportBaseUrl: '/bookorbit'` without changing account identity.

Catalog, annotation, audio and preference responses are validated before mapping. Server IDs are preserved as strings. Server progress units are 0–100; domain progress is 0–1. This includes catalog `readingProgress`: the pinned `assemble-book-cards` test asserts that a file percentage of 45 produces `readingProgress: 45`. A manual reading status can coexist with missing progress. Book details omit this catalog field; load the exact file anchor separately when opening a book. Null/absent genres map to an empty list.

Audiobook manifest timings and bookmark positions are milliseconds. Playback checkpoint JSON contains a stable track ID, track-relative seconds and whole-book source seconds. Both timelines are verified against the manifest before saving; missing durations, missing assets, stale source events and inconsistent positions become explicit conflicts. An old numeric locator is treated as track-relative seconds for progress; audio notes use whole-book source time. A display percentage is never used as an exact locator.

KOReader-aware progress preserves the raw native locator and accepts only the server's CFI/page translation. Native pushes preserve the previous web timestamp, so the adapter uses matching canonical KOReader metadata or explicitly leaves event time unknown. New EPUB positions clear obsolete native locators; positive PDF/comic pages serialize to both page fields, with webtoon offsets remaining local. Bounded partial-MD5 fingerprints can be attached to an exact account/file snapshot and checked against fresh bytes. See [KOReader contract and qualification](koreader.md); no device credential, hash-link or supplied-server mutation is performed.

## Authentication and media

Catalog, collection and smart-scope pages use a one-based Avid API translated to BookOrbit's zero-based wire pages (`page * size` offset). Format and reading-status filters execute on the server before pagination. `getBookCollections(bookId)` returns picker targets; its `bookIds` describes only membership of that selected book, never the complete collection. Server statistics retain seconds, server timezone and source windows; the overview's source totals are not lifetime totals.

The server's JWT strategy supports Bearer headers and the `access_token` cookie. It explicitly does **not** accept query-string tokens. Avid never puts credentials into URLs. Web login uses `clientKind: 'web'` and `credentials: 'include'`; the core also supports `clientKind: 'native'` with an explicit refresh token, as exercised by the disposable fixture. The mobile UI selects the web contract through its generation-bound native authentication bridge so protected playback receives native cookies. The caller owns credential lifecycle and secure persistence; the library database does not store sessions or tokens.

For browser media, use same-origin cookie-authenticated URLs or fetch bytes with `getFileBlob`/`coverBlob`. Blob loading is suitable for documents but buffers the file; `getPlaybackSource(book)` instead supplies controller-compatible streaming tracks and chapters from the audiobook manifest. Track IDs retain BookOrbit file identity; chapter times use source seconds. `streamHeaders()` supplies native transport headers. Cross-origin cookies, CORS, reverse proxies and seek/range behavior require deployment testing. BookOrbit's access cookie is scoped to `/api`; a proxy mounted at `/bookorbit` must rewrite cookie paths to `/bookorbit/api` (including the refresh cookie's more specific path). Fetch calls using a Bearer token can succeed while plain media URLs fail if this rewrite is missing.

## Read-only connections

`new BookOrbitClient(session, {readOnly: true})` rejects **every implemented data mutation before network I/O**. Login and refresh remain available. The catalog query POST is allowed because its pinned server implementation is a read. `SyncCoordinator.flush()` returns immediately for read-only clients.

Pass `{readOnly: true}` to repository checkpoints, note writes and session recording to keep that activity exclusively on-device. Existing pending work is not sent by a read-only client. This is mandatory when exercising the user-provided read-only test server. No mutation tests target that server. Mutation coverage uses mock contracts and the separately created loopback disposable fixture; its real read-only checks confirmed that rejected writes made no HTTP requests.

## Persistence and synchronization

IndexedDB/Dexie uses normalized server URL plus authenticated user ID for every record and outbox entry. Profile names and rotating tokens do not affect scope. Each repository instance has one immutable scope. The sync coordinator refuses mismatched client and repository identities. Later migrations add retained local editions and native journal receipts without changing account identity.

Checkpoint and mutation intent are committed together in one transaction. Pending progress for the same file/format is coalesced; original event time survives retries. Newer events can move backwards. Before sending progress, synchronization reads the remote locator and timestamp; a demonstrably newer remote event becomes an explicit conflict. Exact matches are acknowledged without a write. Annotation tombstones survive stale imports. Local annotation IDs are mapped to server IDs, including subsequent queued edits. An uncertain create is reconciled against remote content; absent or ambiguous matches require review instead of a duplicate-creating blind retry.

Reading activity retries preserve `sessionId`, original start/end and active duration. Repository activity chunks are immutable: an identical retry does not enqueue another operation, even after the first was acknowledged; a conflicting use of the same ID rejects. Callers may supply the actual end time to retain idle gaps. The server deduplicates `(userId,sessionId)` and also permits cumulative duration increases, but Avid's immutable chunk API does not use that mode. BookOrbit silently ignores sessions shorter than ten active seconds, so device totals can differ for very short sessions. API writes use integer seconds and the explicit read/listen/tts activity type; source is omitted for web or explicitly ios/android/watchos for native clients.

Audio playback uses base revision, source timestamp, stable outbox operation UUID and manifest revision. The adapter never falls back to an unguarded legacy audio write. Source-time conflicts and revision changes remain reviewable in the outbox. Generic audio annotations route to audiobook bookmark endpoints: the UUID is retained as both local and server identity, and a retry reuses it. Audio bookmark positions use whole-book milliseconds, independent of playback rate; note title/text synchronize while color remains a device preference.

## Qualification gates and remaining limits

The recovery panel compares exact local and current server positions or annotations before a choice. It rereads the server and transactionally validates the local/outbox snapshot before applying a resolution. A new local/server edit or an active claim invalidates the review. Original payloads and the compared server record remain in an account-scoped recovery receipt, exportable from the panel. Choosing the local version creates a new intent with the time of that explicit choice; choosing the server replaces local state without a server write. Uncertain text-note creation is only reconciled, never blindly recreated. Read-only recovery makes no HTTP requests and can only retain changes on-device. Text progress still has the server-side race described below because its API has no compare-and-swap field.

The reader preference adapter loads `GET reader/defaults` plus exact per-file overrides. EPUB/MOBI mappings cover portable built-in font families, the server font-size range (6–32), line height, column gap percentage, flow and compatible themes. Comic mappings cover layout, explicit direction and compatible background colors. Only changed compatible fields enter durable sparse `PATCH` intents; unknown server fields are preserved. Automatic manga direction unsets the per-file direction. Imported fonts, custom colors, voices, larger device-only font sizes and other unsupported settings remain local. Read-only changes never enter the outbox, including after a later writable reconnect. Settings are cached by account/file; a late server response cannot undo an edit made while it was loading. Patches on the same entity share a transactional claim, and later edits supersede the same fields in older unsent patches. Same-field cross-device writes have no server revision guard and remain last-write-wins. The disposable smoke tests the actual adapter and proves that changing font size/gap preserves an independently changed line height.

Read/listen alignment uses the pinned `epub/:bookId/media-overlay?fileId=` playlist and narration resource routes, plus revisioned audiobook manifests/assets. Explicit file identities and safe archive paths are checked. Authenticated standalone verification reads are bounded to 64 MiB per complete resource, reject ranges/truncation, and cancel on abort. Server playlists have no exact separate-audiobook identity proof; Avid compares their SMIL/text with the actual opened EPUB and requires matching complete audio bytes before constructing an exact source-time map. The server's internal duration-ratio bridge is not treated as an exact conversion API. See [read/listen alignment](read-listen-alignment.md) for API integration, tests and remaining corpus/device gates.

Concurrent coordinators share one account flush and claim outbox records transactionally across tabs. A flush drains new checkpoints that arrive while it runs. An inactive account stops before beginning further operations, preserving remaining intents. Cover object URLs are not persisted in the metadata cache. Browser hooks discard stale connection/query responses and keep local imported resources out of the server outbox.

Writable browser connections flush durable intents on activation and on an online event, then schedule remaining retryable work after its backoff or active lease expires. Read-only connections do not start a sync request or consume an existing outbox. Account changes remove retry listeners/timers; old responses cannot change the active account's notes or status. Successful recovery reloads annotations after server-ID remapping, and a slower initial local snapshot cannot replace those newer results. Pending, failed and conflicting operations remain visible as distinct sync states.

- Password/refresh, route construction, response conversion, read-only guards and synchronization are covered by mock contract tests. The disposable fixture additionally passed actual login/refresh/logout, uploads, file progress, text/PDF/audio annotation CRUD, collections, statuses, preferences, session-ID deduplication and server statistics. Restricted accounts, token expiration during streaming, proxies, concurrent clients and native-cookie behavior still need separate integration evidence.
- Text/PDF/comic progress writes have no client timestamp or compare-and-swap field. Avid avoids replaying observed stale events, but a concurrent update between its read and write remains possible. Missing remote timestamps cannot establish ordering. The source event time remains in the local journal.
- Annotation creates have no client idempotency key. The outbox preserves uncertain results for reconciliation; annotation deletion and external revision races are surfaced as conflicts. There is no assumed general change feed.
- PDF annotations require page geometry (`page`, bounding `rect`, per-line `rects`) and a file ID. Page-number-only notes cannot be uploaded as fake PDF highlights.
- Audiobook notes are supported natively by BookOrbit 3.3.0, so ordinary timestamped audio notes do not require a companion. `getAudioAnnotations(bookId,fileId)` imports them; text/PDF and audio annotation read routes remain separate.
- The shared book model has three display groups while `Book.serverStatus` preserves all eight raw server statuses. `setReadStatus` sends those exact values. A reading status alone does not establish a file position.
- Configured browser/native OIDC callback coordinators are implemented and tested with controlled transactions. Provider registration, actual sign-in and physical callback/process-restart behavior remain separate deployment qualification gates; see [OIDC](oidc.md).
- Library/collection results are paginated. `listCollections()` returns collection identities with empty `bookIds`; load pages through `getCollectionBooks()` to populate membership. Cover and file URLs are authenticated resources, not public URLs.
- This storage schema is the Phase 1 checkpoint and cache foundation. Native SQLite journal source and transactional replay are implemented; physical kill/restart qualification remains. Durable offline media downloads and a complete offline search index remain Phase 2 work.
