The mobile factory in `apps/mobile/src/native-transport.ts` returns the structural `PlaybackTransport` API consumed by the shared application. It creates exactly one backend. A lazy facade avoids allocating audio, native listeners or timers in abandoned React StrictMode render initializers. The native adapter serializes commands, uses owner snapshots/events for state and checkpoints, checks server/account/book/file identity, and ignores stale callbacks. Native load failure clears the source and cannot accidentally play the previously loaded book. Account changes clear native state. `readOwnerSnapshot()` exposes live source identity without URLs; `adoptNative(book)` rereads and verifies account, canonical file, edition and ordered track IDs before attaching to the existing owner without load, seek or play. Its newest native position, rate and sleep policy remain authoritative.

Native playback resolves imported WebView `blob:` audio through an explicit private native receipt store; arbitrary `file:` and `content:` locations are rejected. The shared resolver reads the WebView-owned blob with the original WebView fetch (before Capacitor HTTP patching), transfers ordered chunks of at most 256 KiB, and revalidates native receipts before reuse. Native stores bind pending transfers to secure account generations, require exact scope/book/file/track identity, cap files at 4 GiB and aggregate storage at 8 GiB, expire abandoned partial transfers, and deduplicate only matching content hashes and identities. Local demo imports work without server login only in the exact local demo scope with an empty vault. Completed bytes are excluded from device backup. Receipt ownership survives token rotation but never authorizes another account. Native file playback and process-recovery still require device qualification. Ordered queues require unique source IDs and known positive durations for every nonfinal track. Native owners advance tracks and map book-wide seeks/sleep thresholds to exact track offsets; checkpoints include canonical file identity, track ID/time and optional manifest revision. They do not silently fall back to a second WebView audio owner. Playback status distinguishes actual playback, buffering and failures; native source timing is authoritative. UI polling smooths foreground progress; it does not provide background execution.

## Native durability and replay

The mobile hosts register a native SQLite playback journal (`AvidJournal`). Owner sampling uses native monotonic time and source-position advance at the current rate; it excludes pauses, buffering, seek discontinuities and stalled sampling gaps. Listening activity is split into immutable chunks of at most 15 seconds, flushed at transport boundaries. Exact audio checkpoints append at the existing five-second cadence and on pause/seek/stop. SQLite uses WAL and full synchronous commits; the database is excluded from device backup and contains positions/activity metadata, never media URLs or credentials.

A failed insertion sets a sticky recovery warning in owner snapshots while leaving actual playback status intact. Failed activity chunks and checkpoint fingerprints remain retryable; only a successful durable insertion clears the warning. No-op sampling does not hide a storage failure. Sudden process termination can lose the currently unflushed listening fraction, normally less than 15 seconds; physical disk-full and locked-storage qualification remains.

`drain({accountScope,limit})` returns up to 200 ordered immutable events. JS commits the matching repository transaction/outbox before `ack({accountScope,ids})` deletes those native events. IDs and original event timestamps survive retries. Scope checks prohibit acknowledging another account's event. Activity event IDs equal their session IDs. Root replay receipts deduplicate committed deliveries. Each event retains read-only provenance captured from its source and restricted by current vault policy, so reconnecting with write access cannot change past local-only events into uploads.

For EPUB/PDF/comic position changes, `recordProgress({accountScope,anchor,readOnly})` validates the active vault account and appends an exact anchor; native read-only mode and the caller's read-only flag are combined conservatively. The JS reader then commits its local transaction and acknowledges the native receipt. Browser builds have no native-storage fallback claim. Foreground JS listening accumulation is disabled when the native journal owns those intervals, preventing duplicate activity totals.

The session vault and native journal/adoption sources compiled in native CI at `2920e79`; physical suspend/kill/expiry/disk-error qualification remains required. Native SQLite persistence and IndexedDB/outbox replay are different from a server acknowledgment; journal acknowledgment only follows the local transaction.

## Native sign-in and credential renewal

`AvidOidc` uses ASWebAuthenticationSession on iOS and Android Custom Tabs. A single short-lived PKCE/nonce transaction and callback inbox live in Keychain or Keystore storage, bound to the current vault generation. The exact `avid://oauth2-callback` route, state, redirect, challenge and expiration are checked before returning a one-use transaction. System browser launch resolves immediately; a secret-free event prompts the coordinator to read the durable inbox. Logout/new attempts invalidate prior generations. Provider routing is explicitly configured and requires the BookOrbit/provider callback allowlist; a browser fallback or an arbitrary provider URL is not treated as native sign-in support. See [ASWebAuthenticationSession](https://developer.apple.com/documentation/authenticationservices/aswebauthenticationsession) and [Android Custom Tabs](https://developer.android.com/develop/ui/views/layout/webapps/overview-of-android-custom-tabs).

The `AvidAuth` bridge shares one refresh coordinator between foreground requests and native audio owners. Password login and OIDC token exchanges use isolated HTTP sessions with no shared cookie jar and no redirects. Successful responses can apply staged cookies only while their captured vault generation is still current. Logout waits for any accepted cookie commit, clears credentials/cookies and stops the old owner before resolving; a late HTTP result cannot restore the previous account. Network waits do not hold the commit barrier. This also prevents a superseded sign-in response from changing the live WebView account behind the UI's generation checks.

Refresh requests are deduplicated per account/generation. Every returned access token is verified through `/auth/me` against the saved active user before the coordinator commits the vault and then the matching platform cookies. Fresh-session readers wait for cookie commit completion. The notification to JavaScript contains only account scope and generation; token values stay in the secure session record. The foreground session cursor adopts the latest native generation so its next persistence operation does not overwrite a background rotation. Native sources retain the established BookOrbit web-cookie protocol; the iOS player does not advertise a bearer-only media resource loader.

The native owners schedule renewal near token expiry while playing. Android's resolving data source also preflights every protected range/track open; a single HTTP-401 recovery prepares the existing ExoPlayer playlist at its current state. iOS uses AVPlayer error-log HTTP status for bounded 401 recovery and rebuilds queued AVURLAssets after a committed credential rotation. Both preserve the user's latest position, pause state, speed and sleep policy while a refresh is in flight. A failed renewal surfaces a reconnect warning and never activates a different account. These authentication/renewal sources passed native CI at `96357b2`; real server/device expiry, process-kill, offline and supersession qualification remain.

Android's Continue Reading widget uses an encrypted metadata-only recent store and opaque, account-checked navigation IDs for books of all supported reader kinds. Logout removes its entries and updates the launcher. `AvidAppearance` applies the current light/dark/system setting to iOS interface/status style and Android system bars, including transparent edge-to-edge bars on recent Android versions. Source/compile evidence does not establish physical launcher or system-bar rendering quality.

## Mobile SQLite repository

`AvidLibraryStorage` implements the full repository port on Android and iOS, independently of the native playback journal. Main-host plugins expose all seven typed storage operations; account metadata lives in a private SQLite WAL database with full synchronous commits and per-table revision checks. Atomic multi-table commits validate every observed revision, including empty transactions. Request scopes remain independent of the current network login so old-account final checkpoints and offline reads can complete without authorizing any network access.

Imported file bytes use immutable private receipts with ordered 256 KiB chunks, exact offsets and metadata, a 4 GiB per-file bound and 8 GiB quota. Pending handles bind the process and native connection epoch. Logout and account changes invalidate queued file work after the durable session mutation; same-account token renewal preserves it. Publication validates receipt scope and metadata in the repository transaction. Arbitrary filesystem paths are never accepted.

The shared factory selects the actually registered native bridge and uses the verified copy-before-activation migration from IndexedDB. Missing native storage reports a visible error rather than silently choosing another database. Three factory tests cover host selection, unavailable bridges and migration wiring. The production Swift store passes 15 standalone real SQLite/file tests locally and in the macOS CI job at `430b8b6`. The iOS Capacitor wrapper also compiled in the unsigned app and CarPlay builds at that checkpoint; actual installed bridge calls and iOS data protection remain unqualified. Android passes 62 tests with zero skipped, including 16 storage cases against Robolectric 4.16.1’s native AOSP SQLite engine; the test-only POSIX boundary delegates to actual host filesystem permissions, symlinks and fsync. Both ordinary and opt-in Auto debug APKs, including the Android repository wrapper, compiled in the same successful CI run. These checks do not establish physical-device data protection, power-loss recovery or disk-full behavior. See [repository protocol, migration and qualification](library-storage.md).

### Desktop credentials, networking and provider callbacks

`vault.rs` stores a random encryption key in macOS Keychain, Windows Credential Manager or Linux Secret Service, and encrypts the private session file with AES-GCM. Per-process mutexes and an OS file lock protect generation-based compare-and-swap. Every write and clear changes the generation; atomic replacement and fsync precede success. Missing/locked keyrings and corrupt ciphertext are errors, not silent empty sessions. Plaintext tokens are not written to application files. Real OS keyring prompts, locked stores and process-kill recovery still need installed-platform tests.

Desktop BookOrbit uses the documented native client protocol: access and refresh tokens, isolated HTTP requests and no WebView cookie dependency. Native HTTP accepts only the active server's API routes plus narrowly permitted login/provider-discovery routes. Login/exchange is generation-bound; shared refresh verifies `/auth/me` before vault CAS. A delayed response cannot overwrite logout or another account. The foreground adapter adopts committed native generations. TLS uses OS trust roots; redirects and automatic transport retries are disabled. Responses cross IPC in at most 256 KiB chunks; request bodies are bounded to 64 MiB. Native HTTP and IPC cancellation/account checks are tested; real reverse proxies, private CAs and expiry remain qualification work.

Authenticated desktop audio uses ephemeral opaque `avid-media` resource IDs. Native bounded HTTP range requests add the current active-server bearer token and may perform one shared 401 refresh. Source/book/file/revision identity remains in the shared player; tokens never enter audio URLs. Account changes invalidate media handles. The desktop media engine remains HTML media while the app process runs, so real codec, range, sleep and OS-suspension behavior must be qualified.

Desktop provider sign-in stores the short-lived PKCE verifier, nonce, routing context and callback inbox in separate encrypted vault data, bound to the session generation. System-browser launch validates the exact saved authorization parameters; only `avid://oauth2-callback` with matching state is accepted. Atomic take erases the secret before exchange. Cold/warm deep links use Tauri's native plugin and single-instance integration; notifications contain no authorization code or verifier. Signing, actual installed callback delivery and provider/server allowlisting remain external gates.

### Desktop SQLite library store and search

`library_storage.rs` implements the repository port with real SQLite WAL, `synchronous=FULL`, scoped rows and monotonically increasing per-table revisions. Multi-table reads commit through optimistic CAS; all expected revisions are validated in one SQL transaction, including read-only/empty commits. Account partitions persist independently of the active network account so final local checkpoints and offline metadata can finish after disconnect. No local storage command performs a server request. At `430b8b6`, CI `cargo test --locked` passed 50 tests on Linux and macOS and 47 on Windows, including 13 real temporary-SQLite/file tests, 10 encrypted-vault/CAS tests using a memory key provider, five artwork decode/cache tests, four OIDC parameter/lifetime tests and controlled loopback HTTP/UDP tests. These tests make no production server, physical reader or OS credential-store mutation. The desktop network/CrossPoint TypeScript tests also pass (13 tests).

Local file bytes use private immutable file receipts and ordered 256 KiB IPC chunks instead of full base64 table snapshots. Transfers require exact offsets, size and metadata, enforce 4 GiB per-file/8 GiB aggregate limits, expire abandoned staging, and bind open transfers to the native connection epoch. A SQLite commit validates receipt ownership before publishing the file row. Startup migration copies missing account records and blobs from IndexedDB, verifies matching destination records and file bytes, and records completion atomically. Conflicting destination identities stop activation instead of silently choosing a version; the legacy source remains intact. SQLite tests use actual temporary databases and files; the shared TypeScript parity fixture is supplementary evidence.

macOS Spotlight source uses CoreSpotlight metadata indexing and an Objective-C delegate bridge preserving unrelated Tao activities. Opaque hashed identifiers resolve through a scoped metadata map; active-vault checks precede indexing and navigation. Logout clears the index and late actions cannot reopen another account. Only an installed native handler reports search available. The Objective-C bridge compiled in macOS CI at `430b8b6`; real index/navigation behavior still requires installed-machine qualification.

CrossPoint has a dedicated desktop LAN transport, separate from BookOrbit authentication. It accepts only the pinned status/list/upload/download routes, verifies and pins local-network DNS results, ignores caller credentials, bypasses proxies and refuses redirects or automatic retries. Native cancellation reaches an in-flight upload; uncertain results still require read-only reconciliation. No device was contacted. See [integration evidence](integrations.md).
