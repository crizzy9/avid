# Reader fixtures

`reader.html` is a development-only manual harness, served by Vite at `/@fs/<absolute-repository-path>/packages/readers/fixtures/reader.html`. It is not included in the production app.

- No query: an actual EPUB generated from original Avid sample writing.
- `?format=MOBI`: original DRM-free MOBI6/PalmDB publication with two chapters and byte-offset contents links.
- `?format=PDF`: original two-page PDF text fixture.
- `?format=CBZ`: original three-page synthetic PNG archive.
- `?format=CB7`: the same pages in a real 7-Zip archive.
- `?format=CBR`: the same pages in an uncompressed RAR4 archive.
- `?format=ALIGNED`: an EPUB with two original eSpeak-narrated passages, explicit SMIL fragments, and source WAV timing.
- `?format=HANDOFF`: the actual Reader, linking controls and shared playback controller, using that EPUB plus its identical WAVs as separate standalone assets. This local read-only fixture client never contacts BookOrbit.
- `?format=PREPARE`: production `Reader` and `PrepareReadListen`, real local ASR and matching workers, and the real IndexedDB prepared package store. It compares an ordinary two-paragraph EPUB with a 15.86-second human-narrated LibriSpeech excerpt. No authored timing is present. See [attribution and license](PREPARATION-LICENSE.md).
- `?format=PREPARE&rounded=1`: the same actual audio with BookOrbit-style whole-second manifest duration (16 seconds). It has a distinct revision so a prior exact-duration preparation cannot bypass this recognition check.

For **PREPARE**, open **Prepare Read & Listen**, choose a speech model, then explicitly start preparation. Only that action downloads the selected pinned model and transcribes the real local WAV. The fake client supplies local read-only metadata and bytes, and throws if any ordinary BookOrbit fetch is attempted. Model downloads still require the model host on first use. Preparation can conservatively leave unmatched words or passages; their timing must not be invented.

After preparation, use **Paused first match**, **Paused last match**, and **End gap** to inspect exact forward/backward paused highlighting and clearing. **Follow passage** controls navigation; the source clock, active passage, generated line times, exact preview CFI and saved-checkpoint count are visible. **Inspect highlight text** reads the actual live EPUB markers. Saved-checkpoint count must remain zero in this ephemeral fixture.

**Block fixture audio downloads**, then **Open saved preparation (no ASR)** opens the production prepared viewer from IndexedDB. That viewer verifies stored source hashes and reconstructs the map against the parsed EPUB without running ASR or downloading audio. Its normal Read/Listen controls exercise the persisted package. This is a loaded development-page/media check; a cold offline app-shell launch and native distribution remain separate tests. The fixture and model are not production precache entries.

Regenerate this specific fixture with `node packages/readers/fixtures/generate-preparation.mjs <path-to-LibriSpeech/dev-clean-2/174/168635>`, with FFmpeg available. In a sandbox that cannot launch FFmpeg from Node, first convert `174-168635-0002.flac` to `preparation-speech.wav` with `ffmpeg -y -v error -i <input.flac> -map_metadata -1 -ac 1 -ar 16000 -c:a pcm_s16le -fflags +bitexact <fixture-directory>/preparation-speech.wav`, then pass `--existing-wav` to the generator. The generator checks normalized words against the corpus transcript and derives duration, byte size and SHA-256 from the actual resulting WAV.

For `HANDOFF`, open **Link audiobook**, explicitly select `audio1.wav` for the first EPUB resource and `audio2.wav` for the second, then **Verify selected audio**. **Listen from here** resolves the selected/visible text passage to its exact standalone source time. The player’s **Second audio passage** button pauses and seeks to the second source interval plus 0.2 seconds. **Read from here** validates a freshly fetched EPUB SHA-256 before reopening its exact fragment; the log exposes the target. An immediate return to audio retains the explicitly opened fragment even if both paragraphs fit one page. This fixture exercises a real shared controller and actual WAV files; it does not certify a production server’s edition or a physical native device.

After verification, **Listen alongside text** keeps the EPUB open with the real standalone WAV player. **Follow standalone text** toggles automatic navigation. **Paused first passage**, **Paused second passage**, the exact timed-text buttons, and **End gap** exercise backward/paused highlighting and clearing at the final half-open boundary. The fixture displays the current passage, preview CFI and saved-checkpoint count; following and browsing must not increase the count until **Save displayed position** is explicitly clicked. These additional controls are ready for browser qualification; the earlier handoff evidence does not by itself certify them.

**Save verified fixture offline** stores the original EPUB, both original WAV assets and the verified timing/text in the real `OfflineReadAlongStore`, then opens the production `OfflineDownloads` component with `DexieLibraryStorage`. The descriptor shows two assets and two exact timed passages. The package is visible from the main app's Downloads on the same browser origin and does not need a real server login. This verifies package UI/bytes; a cold app start with its server stopped additionally needs the production service-worker shell. **Inspect highlight DOM** exposes only live publication marker classes, colors and selection for diagnosing the closed-shadow reader fixture.

Regenerate the PNG/PDF/CBZ/CBR/MOBI/aligned EPUB files with `node packages/readers/fixtures/generate.mjs`. In the fixture directory, create the CB7 with `7zz a -t7z sample.cb7 page1.png page2.png page3.png` after deleting the previous sample.cb7.

Manual EPUB checks passed in the Codex embedded browser: opening, table-of-contents navigation, full-book search, note creation, theme and font-size changes. Unit tests decode actual CB7 and RAR4 archives with libarchive WASM, and test SMIL fragment/timing/pause/resume behavior. Additional embedded-browser checks passed: PDF page rendering/cropping/page restoration; CBZ/CB7/CBR real image decoding and page navigation; spreads and RTL setting; webtoon scroll restoration at the exact within-page offset; actual aligned WAV playback with advancing source time, pause, speed, follow toggle, visible passage highlighting, and paused passage skips across distinct audio files. These fixtures do not certify all archive variants, voices, fixed-layout books, native devices, or production distribution builds.

The actual Foliate MOBI parser passes the original MOBI6 fixture: metadata, three reading sections, two TOC entries, and byte-offset navigation to the second chapter. A separate test rejects a protected-file flag before rendering. Selection-to-speech tests cover starting inside a paragraph, inline words split across markup, callback offsets mapped to exact text ranges, and skipping non-linear sections. These deterministic tests do not prove installed-voice playback; real voice availability, speech timing and interrupted cross-chapter playback still need a suitable browser/device runtime.

The root browser test also visibly rendered the MOBI second chapter “The long way home”, switched to continuous scroll, and retained the chapter and selected flow after close/reopen. That runtime reported no installed speech voices, so real voice playback was not certified.
